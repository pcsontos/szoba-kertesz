# 05. alkalom — Az agent kilép a terminálból — Implementációs terv

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (ajánlott) vagy superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `@szoba-kertesz/core` bebizonyítja, hogy nem tudja, honnan hívják: ugyanaz az `askAgent` fut a CLI-ből és egy Express-szerverből, a böngésző tokenenként streamelve kapja a választ — közben a query-agent **szerep szerint** kap képességet (`customer` / `admin`), és adminként egy tool-hívással **delegálni tud a másik agentnek**.

**Architecture:** Négy réteg egymásra: (1) `user-role` — a szerep képességet kapcsol, nem prompt-tiltást: vásárlóként a `delegateToIngest` **nincs benne** a toolkészletben, tehát a modell nem is tud róla; (2) `delegateToIngest` — az ingest-agent egy toolba csomagolva, a query-agent hívja; (3) `apps/server` — vékony Express-réteg, ami csak lefordítja a HTTP-kérést `askAgent`-hívássá; (4) `apps/web` — Vite + React chat, előbb sima `fetch`-csel, majd `useChat`-tel streamelve. A közös loop marad **egy** helyen: a `generateText` → `streamText` váltás az `agent-loop.ts`-ben történik, egyetlen úton.

**Tech Stack:** TypeScript (strict, nodenext), Nx 23.0.1, pnpm 11.12.0, Node v25.2.1, Vitest 4.1.9, **`ai@7.0.66`** + `@ai-sdk/anthropic@4.0.39`, **`@ai-sdk/react@4.0.69`** (pontosan `ai@7.0.66`-ra függ), Express 5.2.1 + cors, React 19.2.x, Vite 8, Tailwind v4 (`@tailwindcss/vite@4.3.3`), Zod 4, PostgreSQL 16 + Prisma 6.

## Tervezési időben feloldott döntések

Futásidőben ezekben nincs mérlegelés.

1. **A szerep konstans + additív CLI-flag.** A doksi `CURRENT_ROLE` konstansa marad az alapértelmezés (élő demó: átírod, és a trace `tools:` sorában azonnal látszik a különbség), mellé egy `--role <customer|admin>` CLI-kapcsoló (T2, additív). **Nem** lesz belőle `.env`-kulcs, és a szerver **nem** veszi kérésből a szerepet — hitelesítés nélkül az jogosultsági felületet nyitna.

2. **A `role` NEM kerül az `AskOptions`-be.** A loop nem tudja, melyik agentet futtatja — nem tudhat szerepekről sem. A szerep a query-agent saját opció-típusán él (`AskAgentOptions extends AskOptions`), és a loop csak a már összeállított toolkészletet látja.

3. **A `SYSTEM_PROMPT` konstans bájtra változatlan marad.** A `CLAUDE.md` invariánsa (`docs/system-prompt.md` ```xml blokkja ↔ `query-prompt.ts`) érintetlen: az admin-blokk **hozzáfűződik**, nem beleíródik. `buildQueryPrompt('customer') === SYSTEM_PROMPT` marad igaz, és ezt teszt is állítja.

4. **Egy út: `streamText` mindig.** A `runAgentLoop` véglegesen `streamText`-re áll; ha nincs `onTextDelta`, akkor is elfogyasztjuk a streamet. Nem lesz két ág — pont az a néma elcsúszás ellen épült a manifeszt-kapu.

5. **Doksi-sorrend a webnél:** előbb `fetch`-es chat (Task 6), utána `useChat`-re átírás (Task 8). Az `App.tsx` kétszer íródik, cserébe a lecke lényege („várakozás + blokk" vs „szavanként épül") a saját repo történetében is látszik.

6. **A shadcn komponensek kézzel másolva.** A `shadcn` CLI `components.json`-je és alias-feloldása az Nx-elrendezésben többet ront, mint javít; a `button` + `input` + `cn` együtt ~80 sor, és a terv tartalmazza őket.

7. **A beágyazott ingest-futás saját nyomot ír.** A `delegateToIngest` a belső `askIngestAgent`-et rendes loopként futtatja, tehát **két** JSONL-sor és két Trace keletkezik egy admin-delegálásnál. Ez szándékos: a HF3 költségbecslés bizonyítékbázisa nem veszíthet el egy valóban elköltött futást.

## Ellenőrzött `ai@7.0.66` tények

Mérve 2026-08-17-én, `MockLanguageModelV4`-gyel, API-hívás nélkül (a próbaszkript futott, majd törölve). **A doksi kódja SDK 6-ra íródott** — ezek az eltérések, és a 2–4. sor a terv gerince:

| A doksi (SDK 6) | Mérve, `ai@7.0.66` |
|---|---|
| `onTextDelta` SDK-hook a loopban | **Nincs ilyen SDK-hook.** A delta az `onChunk`-ból jön: `chunk.type === 'text-delta'`, és a mező neve **`chunk.text`**. (Provider-szinten ugyanez `delta` — a mock ezt írja, a hook azt olvassa.) Az `onTextDelta` a **mi** opciónk lesz. |
| a hiba felszínre jön a stream fogyasztásakor | **NEM.** A `streamText()` nem dob szinkron, és a `textStream` iterálása sem dob — a stream **csendben véget ér**. |
| `await result.text` továbbdobja az eredeti hibát | **NEM.** Első köri hibánál `"No output generated. Check the stream for errors."` — **az eredeti üzenet elveszik**. |
| — | **A legveszélyesebb:** ha a hiba a **második** körben jön, `await result.text` **egyáltalán nem reject** — a futás sikeresnek látszik, üres válasszal. Kezeletlenül ez némán megszüntetné a `[MEGSZAKADT]` naplógaranciát (saját kiegészítés #6). |
| — | Az **egyetlen** hely, ahol az eredeti hiba látszik: **`onError`**. Ezért a loop `onError`-ban elkapja, és a stream elfogyasztása után maga dobja tovább. |
| `prepareStep` / `onStepEnd` | **Változatlan** a `generateText`-hez képest: `stepNumber` 0-alapú, `step.finishReason` lapos string (`'tool-calls'`), `step.usage.inputTokens` lapos szám. A hibás körig lefutott `onStepEnd`-ek megmaradnak (mérve: az 1. kör usage-e megvan, amikor a 2. dob). |
| `result.usage` | Az **összes kör összege** (mérve: 15+10 / 25+20 → `inputTokens: 25, outputTokens: 45`). A `PromiseLike` becsomagolás az egyetlen különbség. |
| `result.responseMessages` | Ugyanaz, mint `generateText`-nél: `['assistant','tool','assistant']`. A `response.messages` továbbra is CSAK az utolsó kör. |
| — | `result.consumeStream()` létezik — ezzel pörgetjük a loopot, ha nem iteráljuk a `textStream`-et. |

**A mock alakja `doStream`-hez** (a `doGenerate` utódja a tesztekben):

```ts
doStream: async () => ({
  stream: simulateReadableStream({
    chunks: [
      { type: 'stream-start', warnings: [] },
      { type: 'text-start', id: 't1' },
      { type: 'text-delta', id: 't1', delta: 'Szia' },
      { type: 'text-end', id: 't1' },
      { type: 'finish', finishReason: { unified: 'stop' }, usage: { /* ágyazott */ } },
    ],
    initialDelayInMs: 0,
    chunkDelayInMs: 0,
  }),
})
```

A `usage` provider-szintű, ágyazott alakja **változatlan** a mai `doGenerate`-hez képest (`{ inputTokens: { total, noCache, cacheRead, cacheWrite }, outputTokens: { total, text, reasoning }, totalTokens }`), és a `finishReason` itt is objektum (`{ unified }`). Lapos alakkal a számok némán `undefined`-ek lennének.

```ts
import { tool, type Tool } from 'ai';
import { z } from 'zod';
import type { ToolOutcome, ToolReporter } from '../tool-outcome.js';
import { askIngestAgent } from '../../agents/ingest-agent/ingest-agent.js';
import type { AskOptions, AskResult } from '../../agents/agent-loop.js';

/**
 * A `delegateToIngest` tool: a query-agent átad egy katalógus-módosítást az
 * ingest-agentnek — TOOL-HÍVÁSKÉNT. Ez a valódi multi-agent kapocs.
 *
 * Amit a szerkezetből érdemes látni: egy AGENT is lehet egy másik agent TOOLJA.
 * A külső loop szempontjából ez ugyanolyan tool, mint a runSql — ugyanaz a
 * ToolOutcome megy vissza a Trace-nek. Belül viszont egy TELJES második loop
 * fut, saját prompttal, saját toolkészlettel és saját DB-jogosultsággal
 * (szoba-kertesz_rw). A query-agent továbbra sem ír: csak DELEGÁL.
 *
 * A beágyazott futás SAJÁT JSONL-sort és saját Trace-t ír — szándékosan.
 * Az a futás valóban elment tokeneket; ha elnyelnénk, a költségbecslés alulmérne.
 */

export const DELEGATE_TO_INGEST_TOOL_NAME = 'delegateToIngest';

export interface DelegateToIngestOptions {
  /** Élő, színes Trace a beágyazott futáshoz is (a külső loop beállítását örökli). */
  readonly print?: boolean;
  /** A beágyazott futás Trace-nyomának kiírása (tesztben false). */
  readonly persistTrace?: boolean;
  /**
   * Teszt-szeam: a beágyazott ingest-futtató. Alapból a VALÓDI `askIngestAgent`
   * — így a produkciós út be van kötve, a specek viszont API-hívás nélkül futnak.
   */
  readonly run?: (
    instruction: string,
    options?: AskOptions,
  ) => Promise<AskResult>;
}

export const delegateToIngestTool = (
  report?: ToolReporter,
  options: DelegateToIngestOptions = {},
): Tool<{ instruction: string }, string> => {
  const run = options.run ?? askIngestAgent;

  return tool({
    description:
      'Átad egy katalógus-módosítási feladatot a katalóguskezelő (ingest) agentnek: új termék ' +
      'felvétele, meglévő termék adatainak javítása, vagy a Shopify-feed alapján frissítés. ' +
      'Az instruction a teljes, önmagában értelmezhető utasítás magyarul — a másik agent NEM ' +
      'látja a beszélgetést, csak ezt a mondatot. Csak akkor hívd, ha a felhasználó ténylegesen ' +
      'MÓDOSÍTANI kér a katalóguson; kérdésre a runSql való.',
    inputSchema: z.object({
      instruction: z
        .string()
        .describe(
          'A katalógus-módosítás teljes utasítása magyarul, önmagában értelmezhetően.',
        ),
    }),
    execute: async (input, { toolCallId }) => {
      const instruction = input.instruction.trim();

      if (instruction === '') {
        const outcome: ToolOutcome = {
          content:
            'Üres utasítást nem lehet delegálni. Írd le egy mondatban, mit kell módosítani a katalóguson.',
          isError: true,
          summary: null,
          sql: null,
          rowCount: null,
        };
        report?.(toolCallId, DELEGATE_TO_INGEST_TOOL_NAME, input, outcome);
        return outcome.content;
      }

      try {
        const result = await run(instruction, {
          print: options.print,
          persistTrace: options.persistTrace,
        });
        const outcome: ToolOutcome = {
          content: result.answer,
          isError: false,
          summary: `ingest-agent · ${result.toolSteps.length} tool-lépés · ${result.usage.inputTokens + result.usage.outputTokens} token`,
          sql: null,
          rowCount: null,
        };
        report?.(toolCallId, DELEGATE_TO_INGEST_TOOL_NAME, input, outcome);
        return outcome.content;
      } catch (error: unknown) {
        // SOSEM dobunk tovább: egy elhasalt belső futás nem viheti magával a
        // külső loopot. A hibából a modellnek olvasható szöveg lesz.
        const message = error instanceof Error ? error.message : String(error);
        const outcome: ToolOutcome = {
          content: `A katalógus-módosítás nem sikerült: ${message}`,
          isError: true,
          summary: null,
          sql: null,
          rowCount: null,
        };
        report?.(toolCallId, DELEGATE_TO_INGEST_TOOL_NAME, input, outcome);
        return outcome.content;
      }
    },
  });
};
```

```ts
import type { ToolSet } from 'ai';
import { buildQueryPrompt } from './query-prompt.js';
import { runAgentLoop, type AskOptions, type AskResult } from '../agent-loop.js';
import { CURRENT_ROLE, isAdmin, type UserRole } from '../../user-role/user-role.js';
import { runSqlTool } from '../../tools/run-sql/run-sql-tool.js';
import { listCategoriesTool } from '../../tools/list-categories/list-categories-tool.js';
import { getClientPreferencesTool } from '../../tools/get-client-preferences/get-client-preferences-tool.js';
import { delegateToIngestTool } from '../../tools/delegate-to-ingest/delegate-to-ingest-tool.js';

/** Kör-limit vásárlónak. */
export const MAX_TOOL_ITERATIONS = 6;

/** Adminnak több kör kell: a delegálás + a végső összegzés plusz körökbe kerül. */
export const MAX_ADMIN_TOOL_ITERATIONS = 8;

const MAX_TOKENS = 1024;

/**
 * A query-agent opciói. A `role` SZÁNDÉKOSAN itt él, nem az `AskOptions`-ön:
 * a közös loop nem tudja, melyik agentet futtatja, tehát szerepekről sem
 * tudhat. A loop csak a KÉSZ toolkészletet látja.
 */
export interface AskAgentOptions extends AskOptions {
  readonly role?: UserRole;
}

export async function askAgent(
  question: string,
  options: AskAgentOptions = {},
): Promise<AskResult> {
  const role = options.role ?? CURRENT_ROLE;
  const admin = isAdmin(role);
  const maxSteps = admin ? MAX_ADMIN_TOOL_ITERATIONS : MAX_TOOL_ITERATIONS;

  return runAgentLoop(
    question,
    {
      systemPrompt: buildQueryPrompt(role),
      buildTools: (report): ToolSet => ({
        runSql: runSqlTool(report),
        listCategories: listCategoriesTool(report),
        getClientPreferences: getClientPreferencesTool(report),
        // A KÉPESSÉG-KAPCSOLÁS: adminnál a kulcs bekerül az objektumba,
        // vásárlónál a spread üresen terül szét — a modell nem is tudja,
        // hogy létezik ez a tool. Ez erősebb, mint egy prompt-tiltás.
        ...(admin
          ? {
              delegateToIngest: delegateToIngestTool(report, {
                print: options.print,
                persistTrace: options.persistTrace,
              }),
            }
          : {}),
      }),
      maxSteps,
      maxOutputTokens: MAX_TOKENS,
      emptyAnswer: `Nem sikerült végső választ adni a megengedett lépésszámon belül (${maxSteps} kör). Pontosítsd a kérdést.`,
    },
    options,
  );
}
```

```ts
/**
 * A `--role` kapcsoló értékének validálása a rendszer HATÁRÁN (a CLI a külvilág).

export function parseRole(value: unknown): UserRole {
```

```ts
import express, { type Express, type Request, type Response } from 'express';
import cors from 'cors';
import { z } from 'zod';
import { askAgent, type AskResult } from '@szoba-kertesz/core';

// app.ts — VÉKONY HTTP-réteg a core agent fölött. A böngészőből érkező kérdés PONTOSAN
// ugyanazon az úton megy, mint a CLI-ben: askAgent → a közös agent-loop. A @szoba-kertesz/core
// framework-független; ez a szerver csak EGY belépési pont (a CLI a másik).
//
// DEBUG: az askAgent-et `print: true`-val hívjuk, ezért a SZERVER konzolján ugyanaz a színes,
// körről körre növekvő trace fut le, mint a CLI-ben. A böngésző csak a választ kapja.
//
// STREAMING: NINCS — ez a /api/chat egyszerre válaszol a teljes szöveggel. A tokenenkénti
// változat a Task 8-ban jön.
//
// Az `ask` injektálható: a specek valódi API-hívás nélkül futnak, a produkciós út mégis
// alapértelmezés. (Ugyanaz a minta, mint az interactive.ts-ben.)

export type AskFn = (
  question: string,
  options: { print: boolean },
) => Promise<AskResult>;

export interface CreateAppOptions {
  readonly ask?: AskFn;
}

/** A kérés HATÁRA — Zod-validálás, ahogy minden külvilágból jövő adatnál. */
const ChatRequestSchema = z.object({
  message: z.string().trim().min(1),
});

export function createApp(options: CreateAppOptions = {}): Express {
  const ask: AskFn = options.ask ?? ((question, opts) => askAgent(question, opts));

  const app = express();
  app.use(cors());
  app.use(express.json());

  app.post('/api/chat', async (req: Request, res: Response) => {
    const parsed = ChatRequestSchema.safeParse(req.body);
    if (!parsed.success) {
      res.status(400).json({
        error: 'A kérés törzsében kötelező egy nem üres "message" mező.',
      });
      return;
    }

    try {
      const result = await ask(parsed.data.message, { print: true });
      res.json({ answer: result.answer });
    } catch (error: unknown) {
      const detail = error instanceof Error ? error.message : String(error);
      res.status(500).json({ error: `Az agent futása megszakadt: ${detail}` });
    }
  });

  return app;
}
```

```tsx
// App.tsx — minimál chat. EBBEN A LÉPÉSBEN sima fetch: a válasz EGYBEN érkezik meg,
// addig a felület vár. A Task 8 írja át streamelőre (useChat) — a különbség
// ("várakozás + blokk" vs "szavanként épül") ekkor lesz demózható.

const API_URL = import.meta.env.VITE_API_URL ?? 'http://localhost:3000';

interface ChatMessage {
  readonly role: 'user' | 'assistant';
  readonly text: string;
}

export function App() {
  const [messages, setMessages] = useState<readonly ChatMessage[]>([]);
  const [input, setInput] = useState('');
  const [pending, setPending] = useState(false);

  async function handleSubmit(event: FormEvent): Promise<void> {
    event.preventDefault();
    const question = input.trim();
    if (question === '' || pending) {
      return;
    }

    setMessages((prev) => [...prev, { role: 'user', text: question }]);
    setInput('');

        />

        </Button>
```

```ts
// convertToModelMessages-szel alakítjuk az askAgent `history` opciójává, így a
// beszélgetés a szerveren is folytatódik körről körre.
//
// STREAMING: a válasz TOKENENKÉNT megy ki (streamText a core-ban, res.write() itt)
// sima szövegként (text/plain) — a TextStreamChatTransport ezt olvassa darabonként.

const ChatRequestSchema = z.object({
  messages: z.array(z.unknown()).min(1),
});

/** A UIMessage szöveges részeinek összefűzése — a nem-szöveges részek kimaradnak. */
function extractText(message: UIMessage): string {
  return message.parts
    .filter((part): part is { type: 'text'; text: string } => part.type === 'text')
    .map((part) => part.text)
    .join('');
}
```

```ts
    const parsed = ChatRequestSchema.safeParse(req.body);
    if (!parsed.success) {
      res.status(400).json({ error: 'A kérés törzsében kötelező a "messages" tömb.' });
      return;

    const uiMessages = parsed.data.messages as UIMessage[];
    const lastMessage = uiMessages[uiMessages.length - 1];
    const question = lastMessage?.role === 'user' ? extractText(lastMessage).trim() : '';
    if (question === '') {

      const history = await convertToModelMessages(uiMessages.slice(0, -1));

        },

  });
```

```ts
export interface ScrollView {
  readonly scrollTop: number;
  readonly scrollHeight: number;
  readonly clientHeight: number;
}

/** Alul van-e a nézet (a küszöbön belül)? Alapból 64 px a tűrés. */
export function isNearBottom(view: ScrollView, threshold = 64): boolean {
  return view.scrollHeight - view.scrollTop - view.clientHeight <= threshold;
}
```

> Mellékesen: az `nx serve` sorosítja a `serve` targetet — ha már fut egy példány, a második csak `Waiting for server:serve:development in another nx process`-t ír, és meg sem próbál bootolni.

**Step 7 — böngésző ✓ (gépi méréssel)**

A Chrome-bővítmény a Task 11 első nekifutásakor nem volt csatlakoztatva; a felhasználó ekkor **kézzel** ellenőrizte az öt pontot a `localhost:4200`-on, és mind átment. A bővítmény engedélyezése után az ellenőrzés **gépi méréssel megismételve** — az alábbi számok a böngészőben, a futó UI-ból származnak.

**1. A válasz szavanként épül ✓**

Egy felsorolást kérő kérdésre a válaszdoboz szöveghossza **19 külön lépésben** nőtt, nem egy ugrással:

```
1.00s len=87   gomb=Állj
9.00s len=163  gomb=Állj
10.0s len=293  gomb=Állj
11.0s len=345  gomb=Állj
12.0s len=464  gomb=Állj
13.0s len=598  gomb=Állj
…
20.26s len=1346 gomb=Állj
20.87s len=1390 gomb=Küldés
```

**2. A `history` működik ✓**

Az előző válaszra visszautaló `"És ezek közül melyik a legolcsóbb?"` kérdés helyesen az ott felsorolt 5 növényre vonatkozott, és az agent újra lekérdezte az árat:

```
Megkeresem a pontos árat a katalógusból!
Az 5 ajánlott közül a legolcsóbb a Kínai pénzfa (Pilea peperomioides) — 2 900 Ft 🪙
```

**3. A markdown renderelve jelenik meg ✓**

A válaszdoboz DOM-ja: `<ol>` × 1, `<li>` × 5, `<strong>` × 8 — és a látható szövegben **nincs** nyers jelölés (sem soreleji `- `, sem `**`).

**4. Felfelé görgetés stream közben nem ugrik vissza ✓**

Stream közben a doboz tetejére görgetve, 5 másodpercen át 200 ms-onként mintavételezve:

```
scrollTop közvetlenül felgörgetés után: 0
scrollTop tartomány a következő 5 mp-ben: [0, 0]
közben a szöveg nőtt: +115 karakter
közben a scrollHeight nőtt: +68 px
```

A tartalom tehát **tovább épült**, miközben a nézet végig a felgörgetett pozícióban maradt — pontosan az `isNearBottom` szándék-rögzítés célja.

**5. Az Állj gomb megállítja a szöveget ✓**

```
gomb stream közben: Állj
hossz a kattintás előtt: 1994
hossz 2,5 mp-cel a kattintás után: 1994   (növekedés: 0)
gomb a stop után: Küldés
```

Böngésző nélkül, gépi úton ugyanezekből előzetesen is bizonyítva volt:

- **history** — HTTP-szinten a `[user, assistant, user]` üzenetsorra érkező visszautaló kérdésre értelmes válasz jött, és az agent **újra lekérdezte a DB-t** a valódi adatokért ahelyett, hogy a beadott előzményt készpénznek vette volna. Ugyanaz a kódút, amit a böngésző hív.
- **auto-scroll magja** — a `scroll.spec.ts` 4 tesztje fedi, köztük a „feljebb olvasva hamis — ilyenkor nem rángatjuk vissza a nézetet”.

## Záró akceptancia

Mind a négy feltétel kötelező (HF3 végrehajtás-design, „Mikor kész egy alkalom"):

1. A kódvezetés-doksi **1–6. lépése** végrehajtva, lépésenként a lefordított ellenőrző paranccsal, **tényleges** kimenettel. (A 7–8. lépés kimarad — lásd Scope.)
2. `typecheck` + `lint` + `build` + teszt zöld, és a darabszám **nem csökkent**: **core ≥ 140**, **cli ≥ 12**, plusz az új `server` (4) és `web` (4).
3. A **manifeszt zöld**, mind a hét saját kiegészítésre — a `doStream`-átírás után is, változatlan állításokkal.
4. A doksi „Végállapot ellenőrzése" blokkja **élőben** lefuttatva (Task 11), a kimenet beidézve.

Plusz két, ehhez az alkalomhoz tartozó feltétel:

5. A `SYSTEM_PROMPT` ↔ `docs/system-prompt.md` **bájtra-azonosság** ellenőrizve (`diff` üres).
6. A `logs/` bizonyítja a delegálást: egy admin-futásból **két** JSONL-bejegyzés (külső + beágyazott), mindkettőben token usage-dzsel.

**A „kész" nem jelenti, hogy commitolva van.** Commit, push, PR külön, kérésre (protokoll 7.).
